# МЕТАЛЛ ПРОММ

Первая версия корпоративного сайта: Next.js App Router, TypeScript, Tailwind CSS 4.
Русская (`/ru`) и кыргызская (`/ky`) версии пяти страниц: главная, каталог, компания, услуги, контакты.

## Запуск

Требуется Node.js 20.9+; в облачной среде проверено с Node.js 24.19.0.

```sh
cd /workspace/metall-promm
npm ci --cache /workspace/.npm-cache --no-audit --no-fund
npm run dev
```

Для production-проверки: `npm run build`, затем `npm run start` (порт 3000).
Существующий checkout уже изолирован облачной задачей; создание Git worktree не требуется.

## Проверки

```sh
npm run build
npm run typecheck
npm run test:e2e
```

Playwright использует `/usr/bin/chromium`, доступный в текущей облачной среде. На другом компьютере укажите `CHROMIUM_PATH` или установите Chromium.
Тесты проверяют страницы на двух языках, поиск и фильтры, скачивание/копирование запроса, мобильную навигацию, отсутствие горизонтального скролла, уведомление WhatsApp, 404 и отсутствие отправки формы на сервер. Для браузерных проверок нужна production-сборка. Тестовый сервер поднимается автоматически, если порт 3000 свободен.

## Изменение информации и ассортимента

- `src/lib/content.ts` — контакты `company`, редактируемые `categories`, товары `products`, тексты обоих языков `copy`.
- Начальные товары — **демонстрационные позиции**, соответствующие категориям. Подтверждённых цен, наличия или характеристик нет.
- Для независимого списка товаров замените начальное `categories.map(...)` явным массивом `Product[]`. Пример структуры позиции (заполнять только подтверждёнными данными):

```ts
// В products: Product[]
{
  id: 'unique-product-id',
  categoryId: 'pipes',
  ru: 'Подтверждённое название',
  ky: 'Ырасталган аталыш',
  subRu: 'Подтверждённое описание',
  subKy: 'Ырасталган сүрөттөмө',
  type: 'pipes',
  image: '/images/your-product.webp',
}
```

Поиск и фильтрация используют список `products`; главная и выбор категории в форме используют `categories`. Для новых категорий задайте уникальный `id`, два названия/описания и `type`: bars, pipes, sheets, channels, angles или beams. Поле `image` необязательно. Собственные фотографии положите в `public/images`; они выводятся через `next/image`. При выборе товара название автоматически подставляется в запрос.

- Услуги: `copy.ru.serviceNames/serviceTexts` и соответствующие поля `copy.ky`. Количество и формулировки можно менять. Реальные истории, проекты и партнёров добавляйте только после подтверждения.
- `company.phone`, `email`, `address`, `whatsapp`, `mapUrl` по умолчанию пусты. Укажите действительные контакты; для WhatsApp — номер с кодом страны. `mapUrl` — проверенная HTTPS-ссылка на карту предприятия. До заполнения показано честное уведомление, карта не имитирует реальное местоположение.
- Фото склада — сгенерированная иллюстрация, **не фотография компании**. Исходник сохранён отдельно в `/workspace/generated_images`, оптимизированный WebP находится в `public/images/warehouse.webp`.
- Администрирование выполняется через данные проекта; отдельной CMS и базы данных в этой версии нет.

## Формы и интеграции

Серверной отправки **нет**. Форма валидирует обязательные поля, скачивает UTF-8-файл или копирует текст запроса; каждое действие сообщает, что заявка не отправлена. Данные не сохраняются сайтом и не передаются на сервер. WhatsApp работает через `wa.me` только после заполнения реального номера; до этого открывается объяснение с возможностью подготовить запрос. Телефон и email становятся активными ссылками после настройки.

Для настоящей отправки нужна отдельная серверная интеграция, например Next.js Route Handler с почтовым сервисом или CRM, проверкой данных, защитой от спама и подтверждением результата. Секреты необходимо хранить на сервере, никогда не в `NEXT_PUBLIC_*` или репозитории.

## SEO и публикация

Страницы предварительно генерируются, имеют `lang`, индивидуальные заголовки, описания, canonical и hreflang. Есть `robots.txt` и `sitemap.xml`. Перед публикацией задайте настоящий домен в `SITE_URL` (пример переменной в `.env.example`) и пересоберите проект: без домена sitemap намеренно пуст, абсолютный адрес не выдумывается. Локальные изображения оптимизируются Next.js; внешний фотохостинг и API для запуска не нужны.

Проверенные инструкции установки и старта сохранены в черновике облачной конфигурации. Сохранение черновика не публикует сайт или среду. Облачная публикация выполняется пользователем в настройках среды; процессы после восстановления запускаются заново по `start_skill`.
